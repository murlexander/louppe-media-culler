## Behavior and limits

`ForegroundWorkCoordinator` is a shared scheduling hint between existing bounded
work units: 180 ms quiet interval, 750 ms maximum deferral, 128 retained waiters.
Visible media promotes shared pending work. Current navigation and native viewport
interaction retire obsolete interests. Optional cache writes yield outside their
serial I/O lane. Quality, fingerprint and metadata work cooperate; explicit Pause,
required decision-save deadlines, transition/Quit barriers and existing lane/access
ownership remain authoritative. Executing native ImageIO/AVFoundation calls cannot
be preempted by this admission policy.

`ArchiveMetadataIndex` stores disposable per-folder observations: at most 40,000
entries/32 MiB per snapshot, 32 folders/256 MiB total. Missing, corrupt, unsupported
or oversized data rebuilds. Fresh complete traversal/pairing and physical revisions
own reuse. Renames and revision changes conservatively reread metadata. Full-size
folders still complete even when only a bounded subset fits the cache. Existing
identity-bound disk thumbnails provide preview reuse; no offline catalog/import mode
was added. Cached metadata is never a file-operation or saved-decision authority.

`OpeningSessionState` accepts validated item observations in 100 ms batches without
reordering its immutable inventory. Current-item metadata is prioritized next after
already-executing work. Ready details use scan facts without another main-thread
read. Richer Info fields and mutation capabilities retain their existing complete
validation requirements. Partial opening never saves decisions.

Pins use a separate durable Application Support document, with 128 pins and
256 bounded position records. Missing/revoked sources remain visible and dimmed,
with Locate and Unpin. Bookmark resolution and reconnect verify volume/folder
identity before opening; same-path replacements cannot adopt a pin. Current and
viewport anchors require the freshly scanned physical revision. Removed/changed
current falls back to a surviving viewport, then the normal opening default.
External file renames that change ctime conservatively lose that anchor.

matching content revisions; render markers/scheduling gaps are not display-frame
